# 架构说明

项目面向湖北交通法规问题，提供一个自然语言问答入口。查找依据、解释条文和提示裁量所需事实在同一条在线链路完成；用户不用切换检索模式或填写结构化事实表单。

业务问答固定使用 hybrid 检索和 DeepSeek。BM25 保留在混合检索内部及算法评测中，不作为离线用户服务。API、网页与 CLI `ask` 共享服务逻辑。

## 模块边界

| 层 | 输入 | 输出与职责 |
| --- | --- | --- |
| 资料导入 | PDF / UTF-8 TXT / Markdown | 带出处、位置和核验状态的条目；上传任务单独登记和续传 |
| 数据仓库 | JSONL、来源清单、上传登记 | 校验后的 `LegalChunk`、按 ID 读取的原文及版本 |
| 向量索引 | 分块后的文档 | 百炼 embedding、Chroma 持久化、增量入库和索引契约检查 |
| 正式法规与上传库检索 | 问题 | BM25 与在线向量召回、父法条去重、RRF 排名；上传资料须为 `ready` |
| 问答链 | 排名原文与问题 | `build_qa_messages()` 拼接上下文，由 DeepSeek 生成解释和补问 |
| 服务校验 | 模型结构化结果、本次候选依据 | 校验状态与引用，回填可信原文和出处 |
| 原文阅读 | 条目 ID 或文档 ID + 版本 | 引用条文、全部已收录内容、明确的覆盖范围 |
| 页面 / CLI / API | 自然语言问题 | 单页回答、缺失信息和可打开的出处 |
| 维护与评测 | 数据、算法参数、题集 | 数据检查、索引管理和算法比较，不提供用户离线问答 |

`runtime.py` 负责装配。在线调用需要百炼密钥、DeepSeek 密钥和可用法规索引；配置缺失、向量失败或模型失败会明确返回错误，不自动改为 BM25 问答。测试通过 `FakeLLM`、HTTPX `MockTransport` 或注入检索器验证流程，不代表实际在线连通。

服务启动和文档导入分别执行。启动时加载已整理条目和配置，不扫描目录重新切分文档、不重新生成已有向量。`chunk-document` 和批量脚本保留 `Document.page_content` 与来源 `metadata`，转换为校验后的 `DraftChunk`；上传任务完成切分和索引后才把文档标为 `ready`。正式库和上传库使用独立持久化数据，问答统一检索。

## 单一问答入口

`GET /` 提供问答页，`/static` 只挂载包内 `web/` 资源。前端同源请求 `POST /api/v1/ask`，只发送自然语言 `question`，由服务决定候选数量与模型配置。API 兼容的可选 `top_k` 不在用户界面展示。

页面展示回答、补问、引用原文和出处。每条解释的引用编号对应 `sources` 中的真实条目；`source_documents` 中其余候选单独标为相关资料，不冒充回答已使用的证据。裁量问题也从同一输入区进入，由提示词要求区分已提供事实、缺失信息、适用边界和条件性解释，不把口语中的省略内容推断为事实。

点击引用调用 `GET /api/v1/articles/{chunk_id}`；点击“查看已收录原文”调用 `GET /api/v1/documents/{document_id}?version_id=...`。指定版本后只展示对应版本内容，不混合不同版本补成所谓全文。引用与文档读取覆盖正式法规和上传资料。

API 与模型返回的内容通过 DOM 文本节点渲染，不能执行为 HTML。来源链接仅允许 HTTP / HTTPS。输入结果只在当前页面保留，刷新后清除；没有多轮记忆，补充信息要与原背景一起重新提交。页面支持键盘提交、窄屏、取消等待、加载和错误重试。取消等待不保证已经发出的上游请求停止执行或计费。

上传管理位于同页的 `#knowledge` 视图，保留统一问答输入与结果。文件通过浏览器 `FormData` 以 `file` 字段发送，不手动设置 multipart boundary。202 响应只代表接收，前端随后查询待处理记录的状态接口；仅 `ready` 提供原文查看和问答入口。状态轮询每 3 秒进行一次，只在上传视图可见且有未完成任务时继续，查询失败后等待手动刷新。读取请求可取消，上传和入库重试不会自动重复提交，失败批次由用户显式重试。上传文件名及错误消息同样按纯文本渲染。

`GET /health` 只检查配置和资料状态，不调用模型。密钥已配置不等于在线模型连通。服务默认本机监听，没有用户鉴权与多用户隔离。

健康响应还返回 `upload_max_bytes`，让页面展示并预检当前服务的文件大小限制；上传是否允许由后端再次校验。

## API 与 CLI 边界

唯一业务问答接口为 `POST /api/v1/ask`，不保留独立法规检索、结构化裁量检查或上传库问答入口。条文和文档 GET 接口负责查看出处。上传管理仍保留：

- `POST /api/v1/knowledge/documents`：提交文件，后台切分和入库。
- `GET /api/v1/knowledge/documents`：列出上传文档。
- `GET /api/v1/knowledge/documents/{id}`：查询进度和错误。
- `POST /api/v1/knowledge/documents/{id}/retry`：继续失败或中断任务。

用户 CLI 为 `ask` 和 `serve`。`validate-data`、`evaluate`、`extract-pdf`、`chunk-document`、`index-vectors`、`vector-status` 等保留为维护命令。`evaluate --backend bm25|chroma|hybrid` 用于比较算法，不切换产品问答链路。

## 数据、版本与覆盖范围

每个 `LegalChunk` 保存 `document_id`、`version_id`、条文原文、来源和核验状态。PDF `pdf_page` 为从 1 开始的真实物理页码，印刷页码由 `printed_page` 单独记录；官网正文用 `source_type=web`、`locator` 和 `official_url`，不得填虚构 PDF 页码。`supporting_sources` 独立保存合并整理所依据的修改决定等来源。

文档响应包含 `document_id`、`version_id`、`title`、`coverage`、`coverage_note`、`articles`。`articles` 是对应文档版本的全部已收录条目，原文不由模型生成。覆盖范围来自资料记录：

| 类型 | 含义与展示要求 |
| --- | --- |
| `full_text` | 整部法规正文已收录，允许标为“整部法规” |
| `selected_sections` | 选定章节或材料，必须解释具体选择范围 |
| `excerpts` | 少量节选条目，不得标为法规全文 |
| `uploaded_document` | 上传文档的已处理内容，不据此认定完整法源或有效性 |

全文收录、转录核对、效力核验和个案适用互不替代。`transcription_checked_on` 有日期时，`verification_status` 仍可为 `pending`；不能因文本完整就宣称现行有效。来源清单、版本合并和阅读稿见 [法规资料库](legal-sources.md)。

`related_excerpt_ids` 用于法条全文与重复节选的检索去重，不表示旧法废止。`superseded` 记录保留按 ID 读取能力，但不进入默认检索。当前尚未实现按案件发生日期自动挑选适用版本。

## 检索、回答与引用校验

正式法规检索先识别明确条目 ID、法规名称、条号和范围约束。指定不存在的条号不会用其他条文填充。BM25 与在线向量分别召回，向量子块去重后回填完整父法条，通过 RRF 融合；已完成上传入库的资料也参与统一问答。查询仅对问题生成向量，原文向量由维护或上传任务预先生成。

`LawService` 检查在线配置后检索一次，通过 `build_qa_messages()` 将排名后的原文一次拼入上下文并调用模型。没有候选依据时直接返回 `insufficient_evidence`；有候选但原文不足时，DeepSeek 也可以明确拒答。同步检索在线程中执行，避免阻塞问答接口事件循环。

模型只能提交解释、引用 ID 和补问。后端校验 JSON、状态组合及每个引用是否属于**本次检索**，然后从可信记录填充 `sources`。即使某个 ID 在库中存在，只要本次没有召回也不能引用。全部候选原文按顺序保存在 `source_documents` 中。问答细节见 [在线问答链](qa-chain.md)。

引用校验保障出处归属，不是语义支持或法律适用审查。主题词范围、否定表达、多事项混问和资料覆盖仍会影响召回；无命中不代表法律不存在。外省问题可能召回湖北材料用于说明区别，不能据此判定适用。答案的 `applicability_status` 固定为 `not_verified`。

## 裁量边界

用户用自然语言描述案件情形，在线回答根据实际检索到的材料解释裁量依据、指出待补充事实，并保留地域、道路类型、规则版本和边界条件。不自动选择处罚档次或输出确定罚款。

裁量条件与幅度保存在可引用的原文条目中，不另存结构化规则草稿。尚未核验的 20、40 平方米边界不能自行改写为确定区间；项目不执行案件选档或罚款计算。

正式规则执行需要可核验的有效版本、完整条件、明确边界和例外规则；当前只提供基于检索原文的解释与补问。
