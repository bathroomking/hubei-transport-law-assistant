# 架构说明

本项目延续“学习路线建议”中确定的方向：Python、DeepSeek、可溯源的单事项 RAG，再逐步接入规则和单智能体。当前把可独立调试的模块先实现出来。

## 模块边界

| 层 | 输入 | 输出 | 扩展位置 |
| --- | --- | --- | --- |
| 自动分块 | PDF / UTF-8 TXT / Markdown | 带来源位置的 `DraftChunk` JSONL | `chunking.py` 的 LangChain 分块器；表格结构和发布流程待扩展 |
| 数据仓库 | JSONL 文件 | 通过结构校验的 `LegalChunk` | 替换为 SQLite/PostgreSQL |
| 检索器 | 问题、top_k | `SearchHit[]` | BM25 / Chroma 可切换，共用范围约束和父法条引用 |
| 向量索引 | 已整理 Document 批次 | Chroma 持久化 collection | 阿里云百炼；显式入库、断点续传和索引契约检查 |
| 模型客户端 | 消息、是否 JSON 模式 | `Completion` | 实现 `LanguageModel` 协议接入其他模型 |
| RAG 服务 | `SearchRequest` | `AnswerResponse` | 在检索后加入重排或证据审查 |
| 事实检查 | `CaseFacts` | `DiscretionCheck` | 核验规则后扩展确定性规则引擎 |
| API / CLI | HTTP / 命令行输入 | JSON | 可接现有业务系统 |
| 本地前端 | 检索问题、结构化事实 | 原文、引用解释、复核事项 | `web/` 内的原生 HTML / CSS / JavaScript |

`runtime.py` 只负责装配，API 和 CLI 使用同一份服务逻辑。测试可以直接注入 `FakeLLM` 或 HTTPX `MockTransport`，不会访问 DeepSeek。

文档导入与服务启动分别执行：`chunk-document` 用 `load_documents()` 读取文档，以 `Document.page_content` 和 `metadata` 贯穿条文整理与 `split_legal_documents()`，通过 `DraftChunk` 校验后保存候选 JSONL。`DraftChunk` 与 `Document` 可以相互转换，持久化格式保持一致。

服务启动只读取正式 JSONL，根据配置使用 BM25、Chroma 或混合 RRF，不扫描原始资料、不重新分块或生成文档向量。向量查询时只向量化问题；同步检索在线程内运行，不阻塞问答接口的事件循环。上传资料使用独立导入任务和 collection，状态为 ready 后参与后续查询，见 [上传知识库说明](knowledge-upload.md)。

问答只检索一次，随后由 `StuffQAChain` 使用 LangChain Core `PromptTemplate`，将排好序的完整原文与问题一次交给 DeepSeek。无命中不调用模型；有命中但内容不足时，模型也可返回 `insufficient_evidence`。后端校验状态与引用，返回实际引用 `sources` 和全部检索资料 `source_documents`，详见 [最终问答链](qa-chain.md)。

## 本地前端

`GET /` 提供工作台，`/static` 只挂载包内 `web/` 目录，已有 `/docs` 和业务 API 保持不变。静态文件声明为 Python 包数据，不需要独立构建。前端按同源相对地址调用接口，无需配置 CORS 或向浏览器提供模型密钥。

页面包含法规检索、带依据问答、裁量辅助和服务状态四个视图。原文详情按条目 ID 读取完整记录，问答把每条解释映射到后端返回的来源，裁量表单不填的值不提交，明确的 `false` 则原样提交。规则及核验状态直接展示后端结果，前端不计算罚款、不推断事实。API 和模型返回的文本使用 DOM 文本节点展示，不作为 HTML 执行；官方来源链接只允许 HTTP / HTTPS。

输入与结果仅存在页面内存中，刷新后清除。请求有加载、超时和错误提示，检索与问答支持取消等待；取消前端等待不保证已经发出的上游模型请求停止计费。健康检查只读取配置，不访问模型。当前部署边界仍是本机开发。

## 数据和来源

每个片段保存 document_id、version_id、item_id、原文、检索文本、来源 SHA-256 和核验状态。PDF 物理页码从 1 开始，`printed_page` 单独保存印刷页码。官网正文使用 `source_type=web`、`locator` 条号和 `official_url`，`pdf_page` 必须为空；数据校验拒绝给网页填写虚构 PDF 页码。

2026-11-04 分两轮补充交通运输及公安交管资料：16 部法规、规章全文 1,280 条，公安裁量总则 22 条和交通管理册 29 项，连同原 5 条记录，共 1,336 条默认检索记录。来源归档在 `data/raw/laws/`，17 份阅读文档在 `docs/legal/`。来源清单与版本问题见 [法规资料库](legal-sources.md)。`scripts/build_legal_corpus.py` 按条或表项离线重建，检查快照 SHA-256、整理稿哈希和条号连续性，不自动宣告法规现行有效。

湖北交安实施办法由官方 2013 年底本按 2017 年修改决定合并，第 56 条的 `source.supporting_sources` 保存修改决定的独立文件、哈希、链接和位置；前端同时展示两处官方来源。公安裁量采用当前通知链接的原始 PDF，保留真实物理页码、印刷页码及跨页位置；一项行为的全部档次保存在同一条记录中。默认服务仅加载已有 JSONL，不在启动时提取或分块 PDF。

首批数据有两个不同的状态：

- **转录已核对**：2026-11-02 对照上传 PDF 第 2 页核对表格文本和列关系。
- **适用待核验**：尚未确认发布通知、施行日期、现行效力、地域适用和法条全文。

因此 `transcription_checked_on` 有日期，但 `verification_status` 仍为 `pending`；`effective_on` 为空。不得把前者当作后者。

`superseded` 条目保留按 ID 查询能力，但不进入默认检索。第一版尚未实现按案件日期选择法规版本；一般检索返回候选依据，不表示已判定其适用。

## 检索策略和局限

先识别明确条目 ID、法规名称和条号；对包含关系的法规名称按出现位置选择更完整名称，避免混淆湖北/国家农村公路条例，以及道路交通安全法/实施条例/湖北实施办法。指定的条号不存在则返回空；公安裁量支持“法规名＋交通管理册第N项”的阿拉伯数字定位。其他问题以人工主题词和“道路＋挖掘/占用”组合召回，再用中文二/三字词项 BM25 排序。

新全文的 `related_excerpt_ids` 标记同条法条的旧裁量表节选，默认搜索选全文；旧 ID 仍可查原记录，裁量规则引用仍有效。这是检索去重，不是法源废止关系。普通公路开挖事项继续保留关联依据；整部法规中的无词项匹配条文不会用于填满 top_k。

BM25 是默认的可解释基线。可选 Chroma 后端共用相同范围约束，在候选内按 Qwen 向量的 cosine 相似度排序，子块去重后回填完整父法条；不使用 BM25 得分截取候选，也不做模型改写。自然语言召回仍受人工主题词限制；无命中不等于法律不存在。扩大主题或增加全库语义召回前需评估误召回。当前组合匹配不能可靠理解复杂否定、多事项混问或从对话补全省略信息。

检索可以返回湖北材料供比较，因此“湖南挖掘公路可以直接用湖北标准吗”仍会召回湖北条目。是否可适用不是检索结论；结构化事实检查会拒绝其他省份，RAG 固定返回 `not_verified`，不会标记案件已核准。

## 引用校验

模型每条解释返回 `text` 和 `citation_ids`。后端先检查 JSON 结构，再检查每个 ID 都属于**本次**检索结果，最后从仓库记录填充 `sources`。库中存在、但不在本次检索里的 ID 也会被拒绝。

这是出处完整性检查，不是语义蕴含检查。模型仍可能引用真实条目却作出不受支持的解释；现阶段需要对照原文复核，后续用标注回答评测集改进。资料中的提示词或用户要求不能改变系统提示词规则，但提示词也不是绝对保证。

## 裁量模块

三档的条件和处罚幅度按原表保存成文本，不自行改成数值区间。当前 `review_status` 只允许 `draft`，也没有“输入完整即执行处罚”的分支。

事实缺失时返回 `needs_facts`；事实齐全仍为 `needs_review`；省份、道路类型或事项不在当前范围时返回 `out_of_scope`。20、40 平方米使用 Decimal 精确比较并提示边界复核；程序不猜测“以上/以下”的区间归属。

以后引入正式规则需同时具备：可核对的有效版本、完整条件、已确定的边界语义、例外规则和回归题。规则版本与文档版本分别维护，建立明确引用关系。
