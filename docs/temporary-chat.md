# 临时单聊天

页面内存保存完整展示记录和下一轮需要的 `chat_state`；服务端不创建会话表，不使用全局聊天列表。刷新、关闭或清空后，下一次请求携带空状态。浏览器后退缓存恢复时也清空；切换页面内的上传标签保留聊天。清空同时中止等待并使旧请求失效，旧响应及其 finally 不得影响新聊天。

页面在输入框上方用一行可横向滚动的标签显示最新一轮的 `follow_up_questions`，最多三个问题。点击被省略的题目可查看完整问句，用户在聊天框自行填写情况后发送。问题列表为空时标签区完全收起。历史中的助手消息仅保存回答正文和引用 ID，临时补问不写入下一轮的 `chat_state`。每轮正文的引用编号仍关联该轮 `sources` 中的原文和页码。

## 请求与响应

仍使用 `POST /api/v1/ask`。首次仅提交 `question` 即可，允许1至2,000字符。后续由前端原样携带上次成功响应中的 `chat_state`：

```json
{
  "question": "那许可需要哪些材料？",
  "chat_state": {
    "summary": "",
    "messages": [
      {"role": "user", "content": "湖北县道挖沟施工需要哪些手续？", "citation_ids": []},
      {"role": "assistant", "content": "现有资料不足，无法回答这个问题。", "citation_ids": []}
    ]
  }
}
```

`messages` 只能是完整交替的 user/assistant 轮次，不接受 system 角色。最多100条，每条最多20,000字符，摘要最多6,000字符，总字符最多100,000；进入模型前还会检查更小的应用预算。输入校验返回422，处理失败不更新前端状态，重试不会重复添加消息。

问答原字段保持兼容，新增 `chat_state`、`retrieval_query` 和 `context_compacted`。`usage` 合计摘要、改写、回答阶段实际返回的可用用量；上游缺少 usage 时不会捏造。`model` 指回答阶段模型，只有澄清/空检索时可为空。客户端的历史、摘要及引用 ID 始终按未核实数据处理，不能改变服务端规则或提供法律权威。

## 每轮执行

1. 检查两项在线密钥，必要时摘要旧历史。
2. 首轮直接检索原问；追问通过 `TASK: rewrite` 生成可独立理解的检索问题。“斜穿过去”等事实补充承接用户前面描述的同一件事。最新的纠正覆盖旧说法，换题则重新开始理解案情。只有无法判断指的是哪件事或哪个对象时，才先澄清。
3. 将完整检索问题交给现有 BM25 / dense / RRF 流程。一般语义查询生成一次问题向量，已有文档向量不重建。
4. 对已定位的同案事实补充，服务按轮次取回用户自己的陈述，与本轮原话一起查找依据。回答使用本轮检索原文，并以用户最新陈述为准。检索时对“斜穿”等词同时查找横过道路的条文，仅用于寻找可能相关的依据。
5. 校验法律结论的引用并回填原文。已能答清本轮问题时，服务省略补问和“实务提示”；只有仍缺会改变结论的事实才提出补问。用户主动询问辨别或核实方法时，可把有帮助的提示放在 `practical_notes` 中。具体罚则、法律义务和程序要求均需本轮条文支持。

若用户询问之前给出的面积等信息，回答可明确复述“按你最新的描述……”，不能说这些是法规记载或核实事实。历史回答和摘要中的法律结论不能代替本轮原文。状态及引用校验不等同于语义或法律适用审查。

## 上下文预算

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `CHAT_HISTORY_TOKEN_LIMIT` | 7000 | 历史超过估算阈值时摘要较早轮次 |
| `CHAT_RECENT_TURNS` | 4 | 正常压缩后最多保留的最近完整轮数 |
| `CHAT_RECENT_TOKEN_LIMIT` | 4000 | 最近轮次估算预算，至少保留最近一轮 |
| `CHAT_SUMMARY_TOKEN_LIMIT` | 1200 | 摘要估算上限，超长输出显式报错 |
| `CHAT_CONTEXT_TOKEN_LIMIT` | 24000 | 每次模型请求估算输入与预留回答之和的应用预算 |

估算函数使用 `ceil(UTF-8字节数 / 2)`，是偏保守的简易近似，并非官方精确 tokenizer 或数学上界。实际用量看模型返回的 usage；这些参数用于控制输入长度、延迟与费用，不代表模型上下文上限。

摘要只处理旧摘要与被移除的完整轮次，保留用户陈述、纠正、待确认项和话题边界。正常情况下不摘要最近一轮。总预算不足时可强制只留最近一轮，再按排名移除较低的整条证据；保留下来的正文不切字，`source_documents` 与实际输入一致。至少一条完整证据仍无法放入时返回413，不用残缺原文强行回答。摘要或改写失败会报错，不静默丢弃事实。

## 验证范围

自动化测试覆盖首次调用、追问改写、事实纠正的数据流、切换话题、独立客户端、清空状态、歧义澄清、非法历史、摘要、用量合并、预算限制和引用隔离。Node 交互测试覆盖成功、失败、取消、重试、清空竞态、页面恢复、临时补问与手动补充、按需打开各轮引用、未引用资料不展开，以及清空后示例仍可使用。
